# 商品識別子管理システム「Crosswalker」 要件定義書

## 1. システム概要

### 1.1 目的

本システムは、品番を起点としてSKU、Amazon ASIN、TQの商品キーをまとめて管理するWebシステムである。
利用者は品番の登録・編集画面で、品番の基本情報と複数のSKUを一括して入力する。登録した情報はWeb画面から検索できるほか、外部システムからAPIで参照できる。

### 1.2 システム構成

- LaravelによるWeb API
- VueによるSPA
- MariaDB（mySQL）
- JSON形式の外部参照API

### 1.3 管理単位

商品データは次の階層で管理する。

- **品番**：
  1. 品番コード
  2. ブランド
  3. カテゴリ
  4. 親ASIN
  - **複数のSKU**：
    1. SKUコード
    2. 子ASIN
    3. TQ品番
    4. TQカラーNo
    5. TQサイズ

## 2. データ要件

### 2.1 品番

| 項目    | 必須  | 内容・例                       |
| ----- | :-: | -------------------------- |
| 品番ID  | 自動  | システム内部で使用するID              |
| 品番コード |  ○  | カラーとサイズを除いた商品コード。例：fisi-05 |
| ブランド  |  ○  | ブランド設定から選択。例：栞             |
| カテゴリ  |  ○  | カテゴリ設定から選択。例：老眼鏡           |
| 親ASIN |     | Amazonの親ASIN。例：B09T32PVM5  |
| 作成日時  | 自動  | 登録日時                       |
| 更新日時  | 自動  | 最終更新日時                     |

### 2.2 SKU

1つの品番に複数のSKUを登録できる。

| 項目      | 必須  | 内容・例                            |
| ------- | :-: | ------------------------------- |
| SKU ID  | 自動  | システム内部で使用するID                   |
| 品番ID    | 自動  | 所属する品番                          |
| SKUコード  |  ○  | 品番、カラー、サイズを含むコード。例：fisi-05-1-10 |
| 子ASIN   |     | Amazonの子ASIN                    |
| TQ品番    |  ○  | TQ上の品番。例：FISI05                 |
| TQカラーNo |  ○  | TQ上のカラーNo。例：1                   |
| TQサイズ   |  ○  | TQ上のサイズ。例：10                    |
| 表示順     | 自動  | 品番内での表示順                        |
| 作成日時    | 自動  | 登録日時                            |
| 更新日時    | 自動  | 最終更新日時                          |

### 2.3 SKUとTQキーの管理方法

SKUとTQキーは必ず1対1であり、登録・編集・削除も同時に行われるため、TQ品番、TQカラーNo、TQサイズをSKUの項目として保持する。

これにより、品番は複数のSKUを持ち、各SKUは1組のTQキーを持つ構造となる。

### 2.4 ブランド

| 項目     | 必須  | 内容            |
| ------ | :-: | ------------- |
| ブランドID | 自動  | システム内部で使用するID |
| ブランド名称 |  ○  | 品番で選択するブランド名  |

### 2.5 カテゴリ

| 項目 | 必須 | 内容 |
|---|:---:|---|
| カテゴリID | 自動 | システム内部で使用するID |
| カテゴリ名称 | ○ | 品番で選択するカテゴリ名 |

### 2.6 一意性と入力規則

| 項目     | 規則                            |
| ------ | ----------------------------- |
| 品番コード  | システム全体で重複不可                   |
| SKUコード | システム全体で重複不可                   |
| 子ASIN  | 入力されている場合はシステム全体で重複不可         |
| TQキー   | TQ品番、TQカラーNo、TQサイズの組み合わせで重複不可 |
| ブランド名称 | 前後の空白を除いた名称で重複不可              |
| カテゴリ名称 | 前後の空白を除いた名称で重複不可              |

品番コード、SKUコード、ASIN、TQの各値は文字列として扱い、先頭ゼロを保持する。

- 品番を選択すると品番詳細画面へ遷移する。

#### 操作要素

#### 機能

- 一覧をページ単位で表示する。
- 品番コードまたは詳細ボタンから品番詳細画面へ遷移する。
- 編集ボタンから対象品番の編集画面へ遷移する。

#### 品番入力項目

| 項目    | 必須  | 入力形式      |
| ----- | :-: | --------- |
| 品番コード |  ○  | テキスト入力    |
| ブランド  |  ○  | 選択欄       |
| カテゴリ  |  ○  | 選択欄       |

| メモ    |     | 複数行テキスト入力 |

#### SKU入力項目

SKUの入力欄を複数行追加できる。

| 項目 | 必須 | 入力形式 |
|---|:---:|---|
| SKUコード | ○ | テキスト入力 |
| 子ASIN |  | テキスト入力 |
| TQ品番 | ○ | テキスト入力 |
| TQカラーNo | ○ | テキスト入力 |
| TQサイズ | ○ | テキスト入力 |
| メモ |  | テキスト入力 |

#### 操作要素

- ブランド追加ボタン
- カテゴリ追加ボタン
- SKU行追加ボタン
- SKU行削除ボタン
- 保存ボタン
- キャンセルボタン

- 品番情報と複数SKUを一度に登録・更新する。

- 必須項目、入力形式、重複を保存前に検証する。
- 入力エラーを対象項目または対象SKU行の近くに表示する。
- 品番と全SKUを1回の保存処理で登録する。
- いずれかの入力値にエラーがある場合は、入力内容を保持して修正を求める。
- 未保存の内容がある状態で画面を離れる場合は確認を表示する。

### 4.6 CSV取込画面

#### 表示・操作要素

- CSVテンプレートダウンロードボタン
- ファイル選択欄
- ドラッグアンドドロップ領域
- 検証ボタン
- 検証結果
- 取込実行ボタン
- 処理結果ダウンロードボタン

#### 機能

- 品番とSKUをCSVから一括登録・更新する。
- ファイル選択またはドラッグアンドドロップでCSVを指定する。
- 取込前にファイル形式、必須項目、重複、登録済みデータとの競合を検証する。
- 検証結果として、新規登録件数、更新件数、変更なし件数、エラー件数を表示する。
- エラーの行番号、項目、理由を表示する。
- エラーが0件の場合に取込を実行できる。
- 処理結果をCSVでダウンロードできる。

### 4.7 サイト設定画面

サイト設定画面は、ブランド設定、カテゴリ設定、API接続設定の3つの設定領域で構成する。

#### ブランド設定

##### 入力・表示項目

- ブランド名称
- 登録済みブランド一覧
- 各ブランドの編集ボタン
- 各ブランドの削除ボタン

##### 機能

- ブランド名称を登録・編集・削除する。
- 品番で使用中のブランドを削除する場合は、対象品番が存在することを表示して削除を中止する。

#### カテゴリ設定

##### 入力・表示項目

- カテゴリ名称
- 登録済みカテゴリ一覧
- 各カテゴリの編集ボタン
- 各カテゴリの削除ボタン

##### 機能

- カテゴリ名称を登録・編集・削除する。
- 品番で使用中のカテゴリを削除する場合は、対象品番が存在することを表示して削除を中止する。

#### API接続設定

##### 入力・表示項目

| 項目 | 内容 |
|---|---|
| API有効状態 | APIの有効・無効を切り替える |
| APIキー | 新規発行または再発行する |
| 許可IPアドレス | API接続を許可するIPv4またはIPv6アドレス |
| 許可CIDR | ネットワーク単位で許可する場合のCIDR |

許可IPアドレスと許可CIDRは複数登録できる。

##### 操作要素

- API有効・無効切替
- APIキー発行ボタン
- APIキー再発行ボタン
- 許可IP/CIDR追加ボタン
- 許可IP/CIDR削除ボタン
- 保存ボタン

##### 機能

- APIの利用状態を切り替える。
- APIキーを発行・再発行する。
- APIキーの値は発行直後に1回だけ表示する。
- APIキー再発行時は旧キーを失効し、新しいキーを有効にする。
- API接続を許可するIPアドレスまたはCIDRを複数登録する。
- APIが有効な場合は、許可IPアドレスまたは許可CIDRを1件以上必須とする。
- 接続元IPが許可設定に一致し、APIキーが正しい場合にAPIへの接続を許可する。

## 5. CSV要件

### 5.1 CSV列

| 列名            | 必須  | 内容      |
| ------------- | :-: | ------- |
| item_no       |  ○  | 品番コード   |
| category_name |  ○  | カテゴリ名称  |
| brand_name    |  ○  | ブランド名称  |
| parent_asin   |     | 親ASIN   |
| item_memo     |     | 品番メモ    |
| sku_code      |  ○  | SKUコード  |
| child_asin    |     | 子ASIN   |
| tq_item_no    |  ○  | TQ品番    |
| tq_color_no   |  ○  | TQカラーNo |
| tq_size       |  ○  | TQサイズ   |
| sku_memo      |     | SKUメモ   |

同じ品番に複数SKUを登録する場合は、品番情報を繰り返してSKUごとに1行記載する。

### 5.2 ファイル形式

| 項目 | 内容 |
|---|---|
| ファイル形式 | CSV |
| 文字コード | UTF-8 |
| ヘッダー行 | 必須 |
| 改行コード | CRLFまたはLF |
| データ型 | すべて文字列として読み込む |

### 5.3 取込規則

- 品番コードとSKUコードをもとに既存データを判定する。
- 未登録の品番・SKUは新規登録し、登録済みの品番・SKUはCSVの内容で更新する。
- CSVに指定されたブランドとカテゴリは、登録済みの名称と一致させる。
- 取込処理はファイル全体を1つの単位として実行する。
- 取込中にエラーが発生した場合はファイル全体の更新を取り消す。

## 6. 外部API要件

### 6.1 API一覧

| メソッド・パス | 内容 |
|---|---|
| GET /api/v1/items | 品番一覧を検索する |
| GET /api/v1/items/{item_no} | 品番と所属SKUを取得する |
| GET /api/v1/skus/{sku_code} | SKUから品番とSKU情報を取得する |
| GET /api/v1/asins/{asin} | 親ASINまたは子ASINから商品情報を取得する |
| GET /api/v1/tq-skus | TQ品番、TQカラーNo、TQサイズからSKUを取得する |

### 6.2 品番取得例

~~~json
{
  "item": {
    "item_no": "fisi-05",
    "name": "商品名称",
    "category": "老眼鏡",
    "brand": "栞",
    "parent_asin": "B09T32PVM5",
    "skus": [
      {
        "sku_code": "fisi-05-1-10",
        "child_asin": "B09EXAMPLE1",
        "tq_item_no": "FISI05",
        "tq_color_no": "1",
        "tq_size": "10"
      }
    ],
    "updated_at": "2026-09-02T00:00:00Z"
  }
}
~~~

### 6.3 API共通仕様

- HTTPS上のJSON形式とする。
- AuthorizationヘッダーにAPIキーを指定する。
- サイト設定に登録された接続元IPアドレスまたはCIDRと照合する。
- URLにAPIバージョンを含める。
- 一覧APIはページ単位で結果を返す。
- 入力エラー、認証エラー、接続元エラー、対象データなし、サーバーエラーを区別する。

### 6.4 主なHTTPステータス

| HTTPステータス | 内容 |
|---|---|
| 200 | 取得成功 |
| 400 | リクエスト形式または入力値のエラー |
| 401 | APIキーのエラー |
| 403 | 接続元IPアドレスのエラー |
| 404 | 対象データなし |
| 429 | API利用回数の上限超過 |
| 500 | サーバーエラー |

## 7. セキュリティ要件

### 7.1 Web画面

- すべての通信にHTTPSを使用する。
- パスワードは安全なハッシュ形式で保存する。
- ログイン後のセッションCookieにSecure、HttpOnly、SameSite属性を設定する。
- 更新処理にCSRF対策を適用する。
- 一定時間操作がないセッションを失効させる。
- Laravel側ですべての入力値を検証する。
- ログイン試行回数に制限を設ける。

### 7.2 外部API

- APIキーを安全なハッシュ形式で保存する。
- APIキーと接続元IP/CIDRの両方を検証する。
- APIキー再発行時は旧キーを失効する。
- リバースプロキシを使用する場合は、信頼済みプロキシを設定して接続元IPを判定する。
- APIの利用回数に制限を設ける。
- エラーレスポンスに内部例外やデータベース情報を含めない。

### 7.3 CSVアップロード

- CSV形式とファイルサイズを検証する。
- アップロードされたファイル名をサーバー内部の保存名として直接使用しない。
- CSVをWeb公開ディレクトリの外に保存する。
- CSVの内容を画面表示する際はHTMLとして解釈されないように処理する。

## 8. データベース構成

### 8.1 主なテーブル

| テーブル | 主な項目 |
|---|---|
| items | 品番コード、名称、ブランドID、カテゴリID、親ASIN、メモ、作成・更新日時 |
| skus | 品番ID、SKUコード、子ASIN、TQ品番、TQカラーNo、TQサイズ、メモ、表示順 |
| brands | ブランド名称 |
| categories | カテゴリ名称 |
| api_settings | API有効状態、APIキーハッシュ |
| api_allowed_sources | API設定ID、IPアドレスまたはCIDR |

品番削除時は、所属するSKUも同じ処理で削除する。

### 8.2 主なデータベース制約

- items.item_noに一意制約を設定する。
- skus.sku_codeに一意制約を設定する。
- skus.child_asinに、NULLを除く一意制約を設定する。
- skusのtq_item_no、tq_color_no、tq_sizeの組み合わせに一意制約を設定する。
- skus.item_idに外部キーを設定する。
- items.brand_idとitems.category_idに外部キーを設定する。
